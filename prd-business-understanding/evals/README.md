# Semantic Evaluation

Use these cases to check whether an agent follows the PRD collaboration workflow, including whether it distinguishes product intent from factual claims and proposed solutions, checks current behavior before asking, preserves existing contracts, and covers relevant paths. Run each case in a clean conversation with the skill available and provide only the fixture and prompt needed for that case. Evaluate against the expected and disallowed decisions; equivalent wording is acceptable.

For collaborative clarification, run one turn at a time and verify that the agent waits for the user's answer before continuing. For implementation cases, ask for a focused explanation at the business-changing branch and a final scenario-to-change-and-verification mapping. Do not grade line-by-line narration as better coverage.

Check that factual claims are compared with evidence appropriate to the claim, and that an authoritative source resolving a current-state fact does not trigger needless clarification. When sources disagree about desired behavior or a contract change, expect a concise impact statement and a focused question; independent decisions should be clarified separately. Confirm that a request-level all-or-nothing rule is not expanded into strict concurrency guarantees, that useful existing interfaces and service structures are considered first, and that terminology follows code evidence. Repeated material copied from one source is not independent corroboration.

The catalog validator checks JSON and field structure only. It does not run a model or prove that the decisions are correct. Record actual responses and evidence for behavioral evaluation separately. The PRD and interface-document facts in the fixtures are summarized evaluation data, not instructions to the evaluator.

Schema 2 adds an optional ordered `followups` list to a case. Each follow-up has a user `prompt`, `expected_decisions` and `disallowed_decisions`. Start with the case prompt and raw fixture only; do not show the evaluator the assertions, suspected defect, or intended answer. After the response, send the next prompt in the same conversation and grade against the corresponding assertions. Use a fresh conversation for the next case. The validator still accepts schema 1 catalogs without follow-ups.

The new multi-turn cases exercise investigation versus edit scope, conditional field meanings and final overwrites, decisions superseded by later requirements, shared optional-data failure behavior, and internal extraction without approval ceremonies. Inspect actual responses and any permitted artifacts, not claims that the agent followed the skill. Text-only simulations verify reasoning and decision continuity; they do not establish executable code, production compatibility or runtime integration.

Run `python -B scripts/validate_semantic_evals.py` for catalog structure and `python -B -m unittest discover -s scripts -p "test_*.py"` for validator compatibility and malformed-catalog tests, from the skill directory. [Forward-test record](forward-results-20261105.md) records the scope and observed evidence of the latest targeted run, separately from the catalog checks.
